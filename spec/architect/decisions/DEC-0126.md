# DEC-0126 — ADCOS Software Deployment Authorization

**Status:** ACCEPTED

## Decision

Authorize a bounded software deployment program for ADCOS 1.1 using the deployment design and implementation plan recorded at:

- `docs/superpowers/specs/2026-09-13-adcos-free-tier-deployment-design.md`
- `docs/superpowers/plans/2026-09-13-adcos-free-tier-deployment.md`

## Scope

Authorized:

- runtime/API deployment surface;
- Neon durable persistence integration where required by existing seams;
- Upstash Redis ephemeral coordination;
- Cloudflare R2 evidence/artifact storage;
- Vercel hosting/deployment configuration;
- deterministic sandbox-provider deployment verification;
- deployment runbook and deployment evidence.

## Constraints

- Architecture 1.1 remains frozen and normative.
- Accepted R7/R8/R9 authorities are consumed by reference.
- No Architecture 1.0 restoration or semantic fallback.
- `ConnectivityContract` remains canonical durable authority.
- Redis is never canonical state.
- Provider SDKs remain behind adapter boundaries.
- Hard contract constraints cannot be silently weakened.
- Software evidence cannot satisfy physical EVID-002..EVID-008.
- No credentials or secret values may be committed.
- Work is isolated on a deployment branch until reviewed and merged.
- Existing ADCOS worker limits remain in force.

## Acceptance

Deployment acceptance is software-class only: a reachable service, durable state, working ephemeral coordination, artifact persistence, deterministic contract-fulfillment path, reproducible deployment, and verified rollback. It does not close or modify the independent physical-validation track.

## Authorization

This decision creates repository-local implementation authority for the bounded deployment scope above until the deployment work is accepted or explicitly revoked.
